# 智能体的员工回复规范

自v0.18.0起，平台对现有和新建智能体统一提供业务表达规范，不需要每个岗位重复填写。普通问题先给结论和必要动作；简单查询通常1–3句，复杂分析、批量清单和用户明确需要的技术内容按需展开。管理员身份不会自动开启技术答复。

岗位配置新增服务对象、常见任务、完成标准、合格回复示例，均为可选项。原职责、规则、流程、回复模板、权限和版本记录保留。管理员可在智能体工作台“岗位配置”编辑；普通成员不可修改。

知识资料可选择“业务资料”或“开发说明”。旧资料默认业务资料，不自动猜用途。日常知识检索只选业务资料，明确编程、调试或技术请求才包含开发说明；管理界面和已获群访问权限的成员仍可查看两类资料。用途更改沿用版本校验和审计，不改变群成员范围。

能力介绍和问候不额外装载知识片段、定时结果与群协作长文。业务问题按相关性选择附加历史，同时保留最近两条协作记录作为指代锚点。SDK实际用户消息、工具调用和结果不裁切、不删除、不重写；历史内容不能当作新指令或写作模板。

回复必须依据实际执行和资料：不得把静态入口说成实时结果，不得把部分完成说成全部完成，不能从校验位错误推断设备不存在或无法提箱。金额、币种、日期、单号和真实附件保留原意；日志、原始错误和技术细节仍可在已有详情/管理员日志查看。平台不靠截断或删除错误来让回答变短。

`lib/response-policy.mjs`编译系统表达规范和每轮短提醒；`lib/pi.mjs`接入所有SDK入口；`server.mjs`为普通聊天、业务任务和定时AI任务注入当前岗位和按需资料。纯程序定时任务的原始输出格式未改写。规则型回复检查只用于离线验收，不自动重试业务操作或伪造执行状态。

`scripts/evaluate-business-replies.mjs`与`qa/response-quality-20261029/cases.json`提供20个业务场景。检查事实、虚假完成、技术噪音、重复与附件等，篇幅只提示人工复核。实际模型记录和对应评分位于同一QA目录；真实回复需对照工具证据检查，规则通过不等于业务全都正确。
