# 海运查询网站研究与智能体首版

研究时间：2026-10-29。研究页面：[海运追踪](https://sea.huodaiagent.com/)、[船公司](https://sea.huodaiagent.com/carriers/)、[港口码头](https://sea.huodaiagent.com/ports/)、[滚装船期](https://sea.huodaiagent.com/roro/)、[箱型速查](https://sea.huodaiagent.com/types/)。

## 结论

**可以独立实现其公开查询工具的大部分行为，但不能把它理解成已经接入所有船司的实时物流后台。** 原站的核心是本地识别单号、参考目录和官方查询跳转。公开功能未要求登录，也未发现自有统一轨迹、实时船期或 AIS 服务；尚不能推断存在何种私有后台。

首版已上线：[海运业务查询助手](https://ai.junweirpa.asia/#agent=01a185a1-6f4a-704b-b265-c36df1972f77)。初始仅管理员为群成员，可按业务需要邀请员工。已保存岗位配置、3 份知识资料及仅本群可用的 `ocean-freight-tools` v2 技能；已有浏览器技能仍可使用。

**31 项自动测试通过**。实际模型任务已成功执行 4 次本地技能调用、0 次工具错误，返回正确箱号、错误校验位、租箱前缀、箱型和港口结果。首轮实测暴露的参数兼容和技能目录枚举重试已修正后复验。本地与公网均返回 HTTP 200，未登录访问群资料返回 401；原有账号、成员、技能和定时计划的数据校验一致，无需重启或构建。

原站没有观察到批量导入、CSV 导出或团队共享历史。我们可以扩展这些能力，但它们不属于已核实的原站功能。

## 技术与交互

公开前端是 **原生 HTML、CSS、JavaScript**，没有需要复制的 React/Vue 运行框架。数据以静态脚本随页面加载，本地字符串搜索；港口最多500个匹配、每页50条，主港使用静态详情页。地图采用 CARTO/OSM 瓦片，提供拖拽、缩放和外部地图链接。

浏览器已验证错误校验位、租箱公司、未知前缀、提单样式和纯数字单号，另测了手选船司、分享预填、目录检索和港口航线分类。正常加载网页执行其前端代码；下载的脚本仅做静态分析，未在 Node 中执行，也未提交反馈/订阅。

实际打开马士基官方结果时，页面显示的是 **2026-07-10 还空箱历史事件，最后更新约3个月前**。这说明官网链接能够到达结果页，同时证明“查到结果”不等于“取得当前 ETA”；智能体应同时说明事件时间、查询时间与来源。

## 业务边界与改进

[BIC 官方说明](https://www.bic-code.org/identification-number/) 区分箱主、设备类别和校验位。校验通过不能证明集装箱存在，箱主也不能直接当作实际承运人。B/L 标签只作参考，不作为已经核验的单号规则。

[BIC API 条款](https://www.bic-code.org/api-terms-of-use/) 限制批量复制建库；[NMFTA SCAC 数据服务](https://scac.nmfta.org/pricing) 有许可和更新要求；[UN/LOCODE 发布目录](https://unlocode.unece.org/publications/) 应按具体版本核对许可、别名及变更。原站港口库自己说明并非全部与官方代码一致，不能直接标成“官方全量库”。

原站反馈在网络失败时也可能显示成功；我们的版本应以实际服务端回执判断。现有 ETA/PierPASS 代码可拆成只读连接器逐家验收，不能直接复用包含写表和客户通知的主入口。

## 完整版本验收条件

1. 每个公开入口有对应功能测试；16个携号连接器逐家验证，失效时清楚回退官网。
2. 港口、BIC、SCAC 数据有明确来源、许可、版本及更新记录，未知和冲突保留原样。
3. 实时查询返回精确箱号、事件时间、时区、采集时间及证据；登录、验证码、无结果分别处理。
4. 智能体已在 Pi 中完成技能绑定、权限和样例任务验收；上表未迁入的全量数据、携号连接器和网页交互仍须逐项补齐，当前未达到完整功能对等。
