# 智能体岗位、知识与团队任务

在智能体聊天页点击顶部“打开智能体工作台”，或右侧“业务任务与人工接手”，可进入任务中心、岗位配置和知识库。

## 岗位配置

管理员在每个智能体分别设置岗位名称、职责、业务规则、处理流程和回复与交付模板。保存后用于该智能体后续的网页、IM 和定时 AI 任务；不会改写已经完成的历史记录。其他群的岗位设置不混用。成员可查看，管理员可维护。

## 知识库

管理员可直接录入知识，或上传 UTF-8 的 TXT、Markdown、CSV、JSON 文件。单篇不超过 512 KiB，单个智能体最多 100 篇、共 8 MiB。Excel 可先导出 CSV；PDF、Word、图片尚不支持直接解析。

成员可检索和查看本群资料。AI 每轮根据任务自动检索相关片段，收到标题、来源文件名、版本与更新时间，并被要求在有资料依据的回答中附来源引用。没有匹配资料时不会把其他智能体的资料混入。当前是本地关键词与中文片段检索；引用依据需要与实际业务时效一起判断。

岗位和资料保存使用版本校验；同事已修改过时会提示重新读取，避免覆盖新版本。资料只作为分析数据，不扩大命令或技能权限。

## 聊天与任务

- “交给 AI”：把要求保存为持久化业务任务，同群按顺序处理；不同群最多四组并行。
- “群内讨论”：保存员工之间的消息，不调用模型。选择 @智能体，或在正文中写独立的 `@智能体`，会转为 AI 任务。
- @同事和引用回复：记录真实群成员 ID 与服务端读取的原消息快照；不会接受客户端伪造的跨群引用。
- 任务中心：查看创建人、负责人、进度、结果和协作事件。聊天消息中的“查看任务”直接打开对应业务任务；不受任务列表当前页范围限制。

任务通过独立执行记录运行，最终文字、已注册图片与文件链接回到业务群；聊天区不展示工具执行过程。窗口关闭后已接受的任务继续运行。未确认的请求使用请求编号去重，避免网络重试造成重复提交。

## 人工接手

成员可接手未分配的任务。已经有负责人的任务，由创建人、当前负责人或管理员转交。接手或转交会暂停排队/执行中的 AI，已有外部操作不会自动回滚。

暂停后可补充资料、交给其他成员、提交人工处理结果，或明确恢复 AI。恢复会依据原要求和补充资料重新处理，先核对已经执行的操作，避免重复写入。负责人变更不会让任务借用负责人的管理员权限；执行仍按当前创建人的有效权限检查。

成员被移出群、账户停用或相关技能被撤销时，任务停止继续执行或输出。服务重启后，正在执行的任务标记中断，需人工确认恢复；不会自动重跑可能已经产生副作用的操作。已排队但尚未执行的任务会保留。

## 兼容与权限

原有定时任务、成员管理、技能授权、微信及企微渠道保持可用。新任务中心主要管理员工从网页提交的工作；定时计划继续在原定时任务页面管理。网页协作结果可供同群 IM 后续查询。

普通群聊与工作台继续仅群成员可见。管理员原有审计/导出入口维持独立审计授权，不扩大普通群接口权限。

## 消息卡片

业务任务结果与执行异常使用消息卡片显示：标题、真实执行状态、结果摘要和任务字段。卡片中的“查看任务”打开这次业务任务，后续人工接手、转交、补充和恢复仍使用任务中心的既有权限与流程。较长结果可展开，图片和文件继续使用本群受控附件的预览与下载。

定时任务投递到群内的结果也可显示为卡片；卡片区分执行结果与投递状态，投递失败不代表业务执行失败。它不会自动判断业务数据是否正确，也不会因显示卡片而重新运行任务。

知识卡片保存本轮实际提供给智能体的资料标题、来源、版本、更新时间与参考片段。“本次参考”表示资料曾提供给模型；“回答已引用”表示本轮正文包含该真实资料的引用标记，并不等于系统已验证每项业务结论。用户不能靠提交一段模型生成的 JSON 伪造这些来源。

点击“查看来源”可复查当时的参考片段。当前资料已更新时，界面分别标注引用版本和当前版本；已删除时保留引用片段并说明原资料已删除，不把当前正文冒充成旧版本全文。只有当前群成员可以读取消息、来源快照及附件。

普通问答和没有卡片的历史消息继续显示文字。卡片采用版本化数据协议，遇到不支持的版本或格式会显示原始文字结果。微信、企业微信继续接收文字及原有附件消息；本次卡片只增强 Web 呈现，不依赖飞书账号或飞书服务。图表卡片不在本批范围。

任务卡片会识别从正文截取的重复摘要，避免与完整结果同时展示。长结果展开后隐藏预览。回复卡片不展示“运行详情”及提交人、耗时等运行元数据，保留业务结果、状态和任务操作入口。Markdown 表格以真实表格展示，兼容模型在相邻表格行之间插入空行；窄屏下表格在自身区域滚动。代码围栏和原始 HTML 保持安全文本行为，已有附件权限与预览方式继续适用。

## 管理员系统日志

管理员可在“管理 → 系统日志”查看运行日志；手机窗口通过顶部页面切换菜单进入。原“操作记录”继续保留用户操作审计。普通员工没有系统日志入口，日志历史、实时流与导出接口均要求当前有效的管理员身份。

日志按时间显示级别、来源、事件和关联编号，覆盖模型、任务、调度、消息渠道及身份权限等运行事件。任务执行失败与结果投递失败分别记录；系统日志用于排查运行问题，不自动判断业务数据是否正确。运行日志记录运行事件；聊天正文在“所有对话”中按智能体查阅，程序标准输出与错误输出在定时任务的“执行日志”中查阅。

可按级别、来源、关键词及北京时间范围筛选，展开单条查看结构化详情。支持暂停与继续接收、自动滚动、加载更早记录和导出脱敏文本。暂停后继续会从上一游标补发仍在保留范围内的日志；超过保留范围会提示缺口，不会声称丢失记录已恢复。

服务保留最近七天且最多二万条运行日志，超限部分会被清理；当前浏览器窗口最多显示二千条。导出最多五千条，超限会提示缩小筛选范围。日志写入和读取均执行脱敏，不提供关闭脱敏的选项。退出、管理员权限失效或账户被停用时，实时连接关闭，页面清除已加载的日志。

运行日志从此功能启用后开始记录，不会把旧服务器输出文件或聊天记录伪装成过去的系统日志。


## 所有对话与程序日志

“管理 → 系统日志 → 所有对话”供管理员跨群查阅，不要求管理员加入该群。SDK 记录读取持久原文，包含压缩前消息和历史分支；群内讨论先读取最近一页，可通过“加载更早讨论”按游标继续读取。群名、创建人与参与人用于列表筛选，正文按选中会话查看。普通员工的群成员权限不变。

“定时任务 → 运行记录 → 执行日志”展示业务程序实际 stdout/stderr（含 print），运行中每两秒读取，支持暂停、继续、刷新和跟随最新。上翻阅读不会自动跳底，任务结束后补读最后输出并停止轮询。Python 子进程启用无缓冲输出；凭据脱敏和既有日志保存/展示上限继续生效。读取这些日志不会重新执行程序，也不会向业务群发送原始输出。

## 智能体执行与排队状态

左侧“运行中”展示有真实执行的智能体，数字统计智能体数量。每个智能体分别显示运行任务数与排队任务数，汇总直接会话、业务任务、定时 AI 及业务程序执行，隐藏的执行会话不重复计数。仅排队时标记“排队中”，不计入运行筛选；人工接手、完成、失败、取消、中断或仅剩结果投递时不计入执行中。计划执行按本次快照中的业务群归属，修改计划不迁移已有运行。

## 管理员查看智能体执行过程

“管理 → 系统日志 → 智能体执行”按执行列出实际工具步骤；业务任务详情可直接点击“查看执行过程”，定时 AI 运行记录可点击“执行过程”。普通员工没有入口，列表和详情接口均独立校验管理员身份，读取日志不会重新执行任务。

新执行实时保存工具名称、调用参数、文本结果、开始/结束时间和耗时。运行期间可自动刷新或暂停；工具失败、任务停止和服务重启中断分别标识。参数及结果在存储和读取时均脱敏，每步参数最多显示 12,000 字符、文本结果最多 32,000 字符，超过上限明确标注截取。列表和步骤均支持分页。这里只记录工具层面实际发生的动作，不记录模型内部推理，也不把脚本一句命令解释成已经核实的内部业务操作。

旧任务从对应的持久会话读取工具调用与结果，标记为“历史记录”；当时没有保存的逐步时间和耗时显示为“未记录”。已取消或中断的执行不把尚未返回结果的工具标成成功。固定业务程序继续从运行记录中的“执行日志”查看 stdout/stderr（含 print），不伪造 Agent 工具步骤。

## 智能体统一管理

管理员通过“管理 → 智能体管理”（`#view=agents`）集中创建和维护可访问的智能体。页面按智能体展示基本设置、岗位与知识、技能分配、协作成员、渠道绑定；名称、头像和执行权限不再从聊天里编辑。岗位与知识复用原有带版本校验的编辑器，配置仅用于后续任务。

右侧聊天面板仅展示群成员及邀请入口，不再展示智能体介绍、工作台配置、技能说明、渠道配置或最近结果。聊天中的任务协作入口保留；岗位和知识在聊天工作台中只读，管理员也从统一管理页进行配置编辑。

全局共享技能自动出现在各智能体，分组技能通过现有接口增减当前智能体授权，保存时重新读取并合并其他智能体的授权。现有服务要求分组技能至少保留一个授权：仅属于本智能体的技能可在此启用或停用。渠道绑定复用原有接口，不抢占其他智能体正在使用的渠道。页面不扩大管理员对非成员群聊天、资料或任务的访问权限。
