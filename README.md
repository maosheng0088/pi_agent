# Pi Web · 公司共享空间

## v0.14.0 专业智能体工作台

默认界面升级为 Vue 3、TypeScript、Vite、Tailwind CSS、shadcn-vue（Reka UI）、Lucide、Pinia 和 VueUse。一个既有群聊对应一个专业智能体协作空间，保留原 ID、成员、聊天上下文、技能授权、渠道绑定和定时结果。新建智能体只允许管理员；每位已加入成员仍可邀请同事，移除与退出规则沿用现有权限。

管理员创建时可以填写名称、选择指定技能、邀请成员及绑定空闲消息渠道。全局共享技能自动可用；独立职责提示词、独立模型及头像上传尚未新增，模型和系统提示词仍使用公司统一配置。员工界面展示可用能力、协作消息与最终结果；命令、工具输出和运行详情留在管理员审计与任务记录。

前端源代码位于 `frontend/`，后端继续使用现有 Node.js/Pi SDK/SQLite。AI 执行沿用 SSE，多人状态沿用轮询；本次没有引入 FastAPI 或浏览器 WebSocket。桌面支持导航、智能体列表、消息区及可收起的资料侧栏，窄屏切换为抽屉列表。

首次安装与构建：

```powershell
npm ci
npm --prefix frontend ci
npm run build:frontend
npm start
```

构建完成后重启服务，访问原地址 `http://127.0.0.1:3210/`。服务端优先提供 `frontend/dist`；`/legacy` 保留旧界面，缺少新构建时自动使用旧入口。界面回退不会回退服务端权限。开发时先启动后端，再使用 `npm run dev:frontend`，Vite 将 `/api` 代理到本机 3210。

需要在旧服务进程继续运行时先发布界面，可在构建后运行 `npm run publish:frontend`，将静态资源更新到兼容入口，并保留 `/legacy.html`。此操作只更新界面；管理员新建智能体的服务端限制须重启加载新后端后生效。手动重启脚本为 `scripts/restart-web-ui.ps1`，会核对进程、请求管理员登录并检查活动任务，不保存口令。

验证命令：`npm test`（后端）、`npm --prefix frontend run typecheck`（前端类型）、`npm --prefix frontend test`（前端行为回归）、`npm run build:frontend`（生产构建）。隔离浏览器 QA 使用本地 mock 模型，不触发真实业务任务。

## v0.13.0 固定业务项目定时执行

管理员定时任务新增「业务项目」类型，直接执行服务端白名单中已配置的项目入口，不调用 AI 生成或解释执行命令。项目保留既有 Python 环境、版本与私有业务配置；可以设置每日北京时间、首次计划日期和结果业务群。默认每个项目每天最多实际启动一次，执行失败、取消或中断不会自动重复执行业务；「补发结果」仍只重试已有通知。业务任务过期超过 15 分钟或跨日时跳过，避免重启后补做陈旧写操作。

业务白名单保存在 `.data/business-tasks.json`，只能由服务端维护，网页不能传入任意解释器、脚本或配置文件路径。配置字段为 `id/name/source/projectId/projectVersion/pythonPath/scriptPath/cwd/registrationPath/timeoutSeconds`，默认参数为注册文件加 `--mode manual`。任务超时取可信配置，最多两小时；原 AI 任务仍为十分钟上限。首次计划日期只限制自动计划，管理员点击立即运行是明确的手动执行。

已配置三个 RPAC 业务项目从 2026-10-29 起每日北京时间 08:00、08:05、08:10 执行，结果进入「业务定时任务」群，原 RPAC 对应计划已停用。详见 [迁移记录](docs/rpac-schedule-migration.md)。

群内只收到任务完成／失败／重复跳过摘要；原始输出写到 `.data/business-logs/`，仅管理员通过运行记录的执行日志查看。进程树在取消、权限撤销或超时时终止。电脑、Pi Web 和业务所依赖的浏览器／网络需要在执行时保持可用。

## v0.12.0 技能共享范围

技能中心支持「全部群聊共享」和「仅指定群聊」，导入 ZIP 时可选择，也可以在技能卡片点击「共享范围」单独修改。指定群聊时至少选一个业务群；新增授权仅能选择当前管理员已加入的群。管理员离开某个原授权群后，可保留或移除已有授权，不能新增该群授权；界面不会读取其群名。新旧技能默认全部群聊共享，更新 ZIP 保留原共享范围，单独修改范围不升级技能内容版本。

群聊技能选择、AI 自动发现、技能命令、批准读取的技能文件和定时任务均使用相同范围。定时任务按绑定的业务群判定可用技能，独立执行记录不会改变授权。范围缩小、停用或删除会中止受影响的运行，下一轮重新加载可用技能；历史聊天结果保留。结果补发只发送已经完成的结果，不重新执行技能。

共享范围控制应用层技能分发与调用；执行模式仍使用本机系统命令，并不提供操作系统级目录或进程隔离。

## v0.11.0 定时业务任务

管理员在「定时任务 → 新建任务」选择已加入的业务群、已启用技能及执行权限。默认「只读文件」仅可读取文件；「执行技能」允许修改文件、运行系统命令和访问业务 API，执行能力按每个任务独立配置。任务使用独立上下文，执行过程保留在管理员的运行记录中；业务群只收到最终结果或失败摘要，群成员可检索并继续追问。

结果自动进入绑定业务群，并通过该群已绑定的个人微信、企业微信渠道发送。运行记录分别显示执行状态、群结果投递状态与渠道待发送／已发送／失败数量。渠道补发只使用已保存的结果，不重新调用模型或业务脚本；补发锁定原渠道及其绑定版本，不向后来新绑定的渠道补发旧结果。个人微信需要扫码人先发一条消息才能获得回复上下文，此前结果保持排队。未绑定业务群的旧任务保持原只读设置，须先绑定才能再次启用或运行。

## v0.10.0 企业微信智能机器人

“消息渠道”现支持个人微信和企业微信。企业微信使用官方智能机器人长连接 SDK，无需公网回调地址。管理员在企微管理后台创建“智能机器人 → API 模式 → 长连接”，保存机器人的可见成员范围，然后在 Pi Web 添加企业微信渠道，填写 Bot ID 与 Secret。Secret 仅在服务端保存，编辑时留空表示保留原值。

将机器人加入目标企微内部群并 @机器人发送一条消息，或与机器人单聊，然后在 Pi Web 的渠道配置中刷新“已发现会话”，明确选择该企微群或单聊并保存。发现会话不会自动授权，也不会调用 AI。管理员再在新建 Web 群或已有群的“消息渠道绑定”中勾选此渠道；一个渠道仅绑定一个 Web 群，一个机器人只允许创建一个渠道。

选中的企微群成员可从企微发起任务，Web 成员可继续同一个 Pi 上下文，群内新消息与 AI 最终回复双向同步；选中的企微群所有成员均可看到这些新消息。历史记录、工具过程、未选中的企微会话不会转发。首版支持文本、语音转写及图文消息中的文字，不处理图片和文件内容。管理员更换凭据、切换会话、解绑或停用后立即撤销旧渠道任务与待发消息。

企微连接会自动恢复，重启保留配置、发现会话与绑定，已有个人微信登录保持。实现使用 [企业微信官方 Node.js SDK](https://github.com/WecomTeam/aibot-node-sdk)，接入步骤可参考 [腾讯云说明](https://cloud.tencent.com.cn/document/product/213/129174)。此处接入的是智能机器人长连接，自建应用回调与微信客服属于其他接入方式。

## v0.9.1 扫码登录状态自动确认

服务端在二维码有效期内自动查询微信扫码状态，关闭扫码弹窗后仍可完成确认；重启后恢复未过期的待确认登录。消息渠道列表自动刷新状态，临时网络错误会重试。微信要求手机验证码时等待管理员输入，二维码过期或验证受限时提示重新扫码。已确认的登录态保留，不需要重复扫码。

## v0.9.0 个人微信与群聊渠道

管理员可在“消息渠道”添加个人微信，使用手机微信扫码并确认；如微信要求配对码，可在弹窗中输入。登录态保存在服务端，二维码在本地生成，无需配置公网回调。管理员新建群聊时可选绑定渠道，也可在已有群的群信息中调整绑定。

一个微信渠道同时只能绑定一个 Web 群，可为同一群绑定多个渠道。扫码微信本人以“微信 · 渠道名称”参与群聊，不要求另建员工登录账号；其文本和语音转写会进入本群并交给同一 Pi 会话处理。本群员工的新消息与 AI 最终回复同步到绑定微信；工具调用、生成中内容和历史记录不转发。扫码后需先在微信向机器人发一条消息，建立回复上下文。

首版支持文本和微信返回的语音转写，图片、视频和文件暂未接入。这里只接入扫码账号本人的机器人私聊，不读取微信通讯录或同步原生微信群。渠道管理与绑定仅限管理员；普通员工继续在已加入的 Web 群聊天。解绑、停用、删除、重新扫码或绑定管理员失去群权限时，撤销旧渠道的待处理消息与运行中任务，防止跨群串发。重启后恢复登录与待处理队列；中断的执行任务保留中断状态，避免盲目重复执行有副作用的业务操作。

手机微信需具备 ClawBot 插件；AstrBot 文档列出的版本要求是 iOS 8.0.70 / Android 8.0.69 或以上。接入方式参考 [AstrBot 个人微信说明](https://docs.astrbot.app/platform/weixin_oc.html)，协议按 [腾讯官方 openclaw-weixin 文档](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md) 独立实现，未引入 AstrBot 运行时或复制其适配器源码。

## v0.8.1 自行退出群聊

非创建人的群成员可在右侧群信息底部点击“退出群聊”，确认后自行退出，群内管理员也可按相同方式退出。退出后撤销群聊与历史记录访问权限，并停止该成员正在执行的任务；个人草稿和当前群视图关闭。历史发言保留，需由剩余群成员重新邀请才能加入。群创建人暂不能退出，以保留群管理责任。

## v0.8.0 移除群成员

群创建人和群内管理员可在右侧成员列表或“群成员 / 添加”名单中点击“移除”，确认后生效。不能移除自己或群创建人。被移除者立即失去群聊、历史、搜索和任务接口访问权限；其正在运行的任务停止，浏览器会关闭对应内容。历史发言保留，允许之后重新邀请，重启不会把历史发言人自动加回群。成员变更保留操作审计。

## v0.7.0 群名与聊天记录搜索

右侧群信息栏可“修改群名”和“查找聊天记录”。所有群成员均可修改群名（1–120 个字符），名称会同步到侧栏和群信息。聊天关键词在当前群内按正文匹配，显示发言人、时间和内容摘要，点击结果可定位到原消息；支持加载更多。搜索仅包含用户消息和最终回复，不显示工具执行过程。非群成员不能改名或检索此群，即使知道群聊链接也无法访问。

## v0.6.1 群成员与可见范围

群聊顶部的“群成员 / 添加”供所有员工使用。按姓名或账号搜索，可多选启用中的员工加入；重复添加不会重复入群。创建人和历史发言人自动进入参与名单，拉人会记录操作人。群聊列表、搜索、历史消息、成员名单和任务接口仅群成员可访问；每位群成员可拉入其他启用账号，新成员可查看群内历史。管理员未入群时通过专门的审计接口查看，不能通过普通群聊接口发言或拉人。无可确认成员的历史记录仅在管理员审计中保留。此处为应用层聊天访问控制，执行命令仍共用本机进程权限，不构成操作系统或共享文件隔离。

## v0.5.3 权限调整

员工与管理员共同使用会话的工具模式：执行模式允许员工通过 AI 运行命令、执行管理员已启用的技能和访问业务 API；只读会话仍禁止命令执行。员工新建会话沿用管理员设置的默认模式，不能自行更改模式。模型配置、技能导入及管理、定时任务管理仍仅管理员可用。员工端隐藏运行信息，聊天隐藏工具执行过程。以下旧版说明中“员工固定只读、不能调用技能”的限制已由本节取代。命令执行不提供操作系统沙箱。

通过真实 Pi SDK 执行模型请求和工具调用。所有员工进入同一个公司空间，共用模型和共享资料，群聊及聊天记录按成员范围可见。群成员可打开并继续自己的群聊，使用该对话已有的上下文；每条发言记录实际发送人。Pi 源码和构建产物位于相邻的 `../pi`。

## 启动与首次设置

需要 Node.js 22.19 或更新版本（推荐使用已安装的 Node 24），以及已构建的本地 Pi；首次安装运行 `npm ci` 安装 ZIP/YAML/二维码后端依赖，无额外前端依赖。

```powershell
cd D:\code\pi-web
.\start.ps1
```

1. 在服务所在电脑打开 `http://127.0.0.1:3210`，创建首个管理员。首次初始化只允许本机访问，完成后关闭此入口。
2. 在“模型与共享配置”检查模型和资料目录。已有 MiniMax 配置保留，密钥不回传浏览器。
3. 在“员工管理”创建员工账号，设置初始密码；员工登录后可修改自己的密码。
4. 同局域网员工使用服务电脑的 IPv4 地址访问，例如 `http://192.168.1.43:3210`。地址取决于网络，电脑需要保持运行；无法连通时检查网络和 Windows 防火墙是否允许本服务端口。

若 Windows 防火墙拦截访问，在管理员 PowerShell 中运行 `D:\code\pi-web\enable-lan.ps1`。脚本仅允许专用网络中本地子网访问当前 Node 程序的 TCP 3210 端口，不更改网络类型。

用户名为 3–48 位字母、数字、点、下划线或短横线，首字符为字母或数字；新建或修改密码须为 8–128 个字符，登录兼容已有及已导入的较短凭据。无公开注册和默认密码。

`start.ps1` 默认监听 `0.0.0.0:3210`。仅本机使用可运行：

```powershell
.\start.ps1 -BindAddress 127.0.0.1
```

直接执行 `node server.mjs` 默认只监听 `127.0.0.1`；通过 `PI_WEB_HOST`、`PI_WEB_PORT`、`PI_WEB_DATA_DIR` 和 `PI_SDK_PATH` 可配置监听、数据目录和 SDK。启动脚本也接受 `-Port`。

## 共享与权限

| 能力 | 员工 | 管理员 |
| --- | --- | --- |
| 使用共享模型和资料 | 可以 | 可以 |
| 查看、继续任意共享对话 | 可以 | 可以 |
| 停止自己发起的运行任务 | 可以 | 可以 |
| 停止其他人正在运行的任务 | 不可以 | 可以 |
| 管理账号、模型密钥、系统指令、目录 | 不可以 | 可以 |
| 导出聊天、查看操作记录 | 不可以 | 可以 |
| 创建、编辑、启停和调用 Skills | 不可以 | 可以 |
| 配置、手动运行、取消定时任务及查看运行记录 | 不可以 | 可以 |

对话创建人与逐条发言人分别记录，不把创建人当成所有发言的作者。仅本群成员可以查看群聊历史；界面隐藏工具执行过程。管理员另有聊天审计与单个会话 JSON 导出；可按参与成员、会话标题/员工关键词和日期查询，查询关键词匹配标题和员工信息，不是消息全文检索。管理员查询、查看和导出也会记录操作日志。

网页在可见时自动同步共享列表与当前对话。同一对话一次只允许一个运行任务，其他人看到运行者和等待状态，完成后可以接着发送；不同共享对话可以并行处理。对话可分为不同话题，各群仅对群成员开放。

普通员工固定使用只读工具，不能修改共享目录或工具权限。文件工具校验真实路径、拒绝 `..` 和指向目录外的链接；共享资料目录必须与服务 `.data` 目录分开。管理员可点击聊天输入框下的“启用脚本执行”，为当前对话开放文件修改和系统命令；“切换为只读”可收回。设置页的工具模式仅作为新对话默认值，已有对话须单独切换，运行期间不能切换。管理员可为自己发起的运行启用编辑和命令工具，其他员工继续该共享对话时仍为只读，命令执行不提供操作系统沙箱。

密码使用 scrypt 哈希；登录使用服务端会话和 HttpOnly Cookie。重置密码或停用账号会撤销已有登录并取消该账号的运行任务，自己改密后保留当前新登录。登录态最长 12 小时；失败登录有限速。启用中的最后一个管理员不能被停用。

## 管理员 Skills 与定时任务

“技能中心”和“定时任务”仅管理员可管理；对应接口也校验管理员权限。业务群成员可查看和查询最终任务结果，工具执行过程保留在管理员运行记录中。

在“技能中心”点击“导入 ZIP”，上传一个完整技能包。ZIP 可直接包含 `SKILL.md`，也可多一层技能文件夹；只能包含一个 `SKILL.md`，其 YAML 头须填写 `name`（小写字母、数字、短横线）和 `description`。正文和 `scripts/`、`references/`、`assets/` 等配套文件一起保存，支持普通存储或 Deflate 压缩。ZIP 最大 10 MB，单文件解压后最大 10 MB，合计最大 40 MB、最多 500 个条目；拒绝加密文件、链接、路径越界及 Windows 文件名冲突。

导入后自动打开正文及文件清单预览，默认停用。确认后在技能卡片点击“启用”；已有技能使用“更新 ZIP”上传新版本，任务引用保持同一技能 ID，正在运行的任务继续使用旧版本。导入会保留原始 SKILL.md 元数据及二进制素材。包内脚本不会在导入时运行，也不会自动安装依赖；执行仍受群聊或定时任务设置的执行权限限制。

管理员聊天时可选择已启用的技能，或输入 `/skill:技能名称 任务说明`。模型可读取批准的技能包文件；明确选择时会给出包目录，正文中的相对路径以该目录为基准。员工可调用已启用技能，但不能导入或管理技能；回复按群成员范围可见。

在“定时任务”填写任务提示词，选择业务群，可选一个技能，支持单次、每天、每周和固定分钟间隔，时区固定为北京时间（`Asia/Shanghai`）。新建表单默认停用，执行权限默认为只读文件。任务以创建管理员的身份使用共享模型和资料；每次使用独立上下文，最终结果发布到业务群。手动“立即运行”也会真实调用模型并记录结果。任务提示词、技能、权限与目标群在提交时保存快照，编辑计划不改变已提交的运行。

计划和运行记录持久化到 SQLite；同一任务不会重叠执行，运行超过 10 分钟会停止，管理员也可以取消。技能被停用、创建人被停用或失去管理员身份时，运行会失败并留下原因。已有任务引用的技能须先解除引用才能删除。

调度由本机 Pi Web 服务执行，电脑和服务需要保持运行。服务恢复后，错过的单次任务补跑一次，重复计划合并错过的次数、仅补跑最近一次；重启前未结束的运行标记为“已中断”，不会自动重试该次运行。已完成但尚未提交的结果继续投递，外部消息由持久化渠道队列重试。

## 数据和升级

- `.data/config.json`：共享模型与目录配置，包含服务端模型密钥。
- `.data/workspace.sqlite`：账号、登录态、共享对话索引、逐条发言人、技能正文及版本、计划、运行记录和操作审计，采用 SQLite WAL。
- `.data/sessions/`：Pi 原始会话文件，可在服务重启后恢复上下文。
- `.data/skills/<id>/v<version>/SKILL.md`：技能的 Pi 原生版本文件，由技能中心维护；旧文件保留供已经开始的运行使用。管理员运行时仅允许读取已批准的技能文件，不能藉此浏览其他服务数据。
- 旧版 `.data/sessions.json` 首次启动自动导入数据库，原文件保留；导入幂等，不会重复创建对话。所有旧对话也加入共享列表；原本未记录使用人的发言继续标记未知，不猜测作者。已知账号归属的旧版记录可恢复原作者。

`.data` 已加入忽略规则。备份时先停止服务，再复制完整 `.data`，包括 SQLite 的伴随文件；恢复整个目录即可。备份也包含凭据，应保存在受控位置。员工不能从网页删除审计数据，当前版本不自动清理历史记录。

## HTTPS 域名部署

局域网测试可使用 HTTP。配置正式 HTTPS 反向代理时，设置公开地址并保留原始 Host：

```powershell
.\start.ps1 -BindAddress 127.0.0.1 -PublicUrl https://agent.example.com
```

`PI_WEB_PUBLIC_URL` 只接受无路径的 HTTP/HTTPS 地址。HTTPS 域名请求会使用 Secure Cookie，服务不会盲目信任代理头。代理须保留 Host、关闭 SSE 响应缓冲并允许长连接。先在本机完成管理员初始化，再开放代理入口。

这是单公司空间版本，不包含跨企业租户、企业微信认证、审批流或容器执行隔离。

## 本地批量导入账号

`scripts/import-users.mjs` 从标准输入接收 JSON 数组，每行字段为 `username`、`displayName`、`password`，可选 `role`（默认 `member`）。账号必须是字符串，以保留前导零。导入前先停止服务并备份 `.data`；使用 `--data-dir` 指定数据目录，默认使用本项目 `.data`。

脚本先校验整批数据，再生成带独立盐的 scrypt 哈希，在一个数据库事务中写入；默认跳过已有账号，不覆盖已有密码或权限。输入只在内存使用，结果和审计不包含密码。首次导入需包含明确指定的管理员。仅当确实需要兼容用户指定的首次短密码时，本地命令可显式传入 `--allow-short-initial-admin`；此选项不放宽网页新建或改密规则。登录可以验证已导入的历史凭据，新建和改密仍要求 8–128 位。
